桌面端 AI 编码智能体应用 OurCode 的「多 Agent 指挥台」主界面（1440×900 桌面视口），方案 D，参考 Linear / Mission Control 仪表盘架构：一个总监（用户）同时指挥多个并行工作的 Agent，主体是 Agent 卡片网格，配合顶部 KPI 条与底部总监指令条。浅色玻璃拟态风格：应用背景 #f6f7fb，白色圆角卡片（圆角 16px，卡片间 8-12px 间隙，hairline 描边 rgba(15,23,42,0.08)，极浅投影），主色 #0058bc 仅用于主按钮、选中态、进行中状态；文字 #0f172a / #334155 / #64748b；成功 #16a34a、警告 #d97706、错误 #dc2626；界面字体 Plus Jakarta Sans，代码 JetBrains Mono；面板标题 12px 大写加宽字距；强调色克制，无大面积渐变。所有 UI 文案为简体中文。

布局结构：
1. 顶栏（高 52px）：左 OurCode logo + 「指挥台」，中间搜索框「搜索 Agent、任务…」，右侧头像 YG 与「● 全部系统正常」。
2. KPI 条（四张并排小卡片）：「活跃 Agent 3」「今日完成 12」「待我审批 2」（带蓝色数字角标，卡片有警示浅黄描边）、「Token 消耗 86k / 400k」附细线进度条。
3. 主体 Agent 卡片网格（3 列，每张卡片 380px 宽）：
   - 卡片一「前端工程师」（● 执行中）：头部角色头像（蓝色圆角方块）+ 名称 + 状态徽标；中部当前任务「修复 Composer 抖动」+ 细线进度条 3/5 步；最新动作一行等宽小字「edit_file ChatInput.tsx +142 −0」+ 时间 14:03；底部一行轻量按钮「查看轨迹」「审批 1」（蓝色文字按钮）。
   - 卡片二「测试工程师」（● 执行中）：任务「补 OAuth2 回归测试」，进度 5/8 步，最新动作「run_command pnpm test ● running」。
   - 卡片三「文档秘书」（✓ 已完成 绿徽标）：任务「生成本周变更说明」，产物 chips「CHANGELOG.md」「周报.docx」。
   - 卡片四「数据分析师」（⏸ 排队 灰徽标）：任务「周报数据看板」，排队原因「等待前端工程师完成」。
   - 卡片五为虚线描边的「+ 派驻新 Agent」空卡。
4. 右侧滑出的审批抽屉（宽 360px，覆盖在网格之上，白色玻璃卡）：标题「待我审批 2」；一张审批卡「前端工程师 · run_command：$ pnpm test:unit --filter composer」+ 按钮「拒绝」「允许一次」（蓝色主按钮）；一张审批卡「测试工程师 · 写文件 e2e/oauth.spec.ts」+ 同样按钮组。
5. 底部总监指令条（贯穿全宽，白色圆角胶囊卡）：左侧徽标「总监指令」，输入框占位「给全体或指定 Agent 下达指令，@ 选择对象…」，右侧「@ 指定 Agent ▾」与蓝色发送按钮。
