# 生成单元测试（generate-tests）

为工作区中的代码模块自动生成并运行单元测试，迭代直至测试通过。

## 前置条件

- 确定测试目标：`target`（文件或目录）。若未指定，以当前打开的文件为基准推断其模块。
- 先判断项目测试框架：读取 `package.json`（vitest/jest/mocha）或 `pytest.ini`/`pyproject.toml`（pytest）。若项目无测试框架，选择并配置最合适的一个。
- 若目标模块较大，可派生 `test-generator` 子智能体执行「读源码 → 写测试」的独立子任务。

## 执行步骤

1. **分析源码**：读取目标文件及其直接依赖，识别：公开函数/类签名、输入输出、边界条件、错误分支、被 mock 的外部依赖（文件系统、网络、时间）。
2. **确定测试位置与命名**：遵循项目现有约定（如 `__tests__/`、`*.test.ts` 与源码同目录、`tests/test_*.py`）。
3. **编写测试**：覆盖以下用例（按优先级）：
   - 正常路径 + 典型输入/输出断言
   - 边界条件（空输入、极值、超长、负值）
   - 错误分支（异常抛出、非法参数）
   - 关键依赖使用 mock，保证测试确定性
4. **运行测试**：用 `run_command` 执行项目的测试命令（如 `npx vitest run <target>`、`pytest <target>`）。
5. **验证整体健康**：
   - 运行 typecheck（`npm run typecheck` / `tsc --noEmit`）确认新增测试文件类型正确。
   - 项目有覆盖率命令（如 `npm run test:coverage`）时运行并确认目标模块覆盖率合理；测试文件本身不计入覆盖率统计。
6. **迭代修复**：
   - 测试失败 → 区分「测试写错」还是「源码 bug」：前者修正测试，后者在报告中指出（**不擅自修改被测源码**，除非用户明确允许）。
   - 反复运行直至全部通过或达到合理轮数上限。
7. **输出结果**：列出新增/修改的测试文件、覆盖的用例清单、测试运行输出摘要（通过/失败数量）。

## 规则

- 可以修改/新增**测试文件**，但默认**不修改被测源码**；确需修改时先向用户说明。
- 测试必须能独立重复运行（确定性、无外部依赖泄漏）。
- 遵循项目现有测试风格与断言库，保持一致性。

## 完成判定

所有新增测试通过（或明确报告遗留失败与原因），并给出覆盖用例清单。
