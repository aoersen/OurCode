# 桌面应用 GUI 自测（app-gui-test）

用 computer-use 类 MCP 工具对**桌面应用**做真实界面自测：
启动应用 → 读取无障碍树（UI Automation）建立基线 → 点按 / 输入 → 重新读取树断言结果 → 输出报告。
与 `ui-self-test`（网页）互补：本技能测桌面壳层——窗口、菜单、面板、对话框、快捷键路径。
**不修改被测源码**，只验证行为。

## 前置条件

1. **确认目标与启动方式**：`target`（应用入口，如打包产物 `release-*/xxx.exe`、`npm run dev`、`electron .`）。
   未指定时按项目 package.json 的 `main` / `scripts.dev` 推断。
2. **确认 computer-use 工具可用**：需要 `open_application`、`list_apps`、`list_windows`、
   `get_app_state`、`left_click`、`type`、`key`、`screenshot`、`wait`（来自 computer-use MCP；
   ZCode 环境由官方 computer-use 插件提供，其他环境用暴露同等工具面的 MCP，见 docs/APP_GUI_SELF_TEST.md）。
   - 工具缺失时向用户说明如何启用，不要硬试。
3. **确认无残留实例**：先 `list_apps` / `tasklist` 检查目标应用是否已在运行。
   - 已运行实例若是**用户自己的会话**，不要动它；改用独立的 `--user-data-dir`（Electron）或换端口再启动测试实例。
   - 验收依据：优先读取工作区测试计划 / 需求清单 / README 功能说明；没有则基于界面实际功能归纳待验证项，先向用户确认范围。

## 执行步骤

1. **启动应用**：用 `run_command`（`start "" "path\to\app.exe"`、`npm run dev` 等）或 `open_application` 启动，
   然后 `wait` 数秒等待就绪；用 `list_apps` 拿到进程 id（pid）。
2. **建立基线**：`get_app_state`（`detail: compact`）读取无障碍树，确认窗口结构：
   面板/按钮/输入框/菜单齐全、无异常弹窗。必要时 `include_screenshot: true` 截图留基线。
3. **逐项验证**：按验收清单逐条执行，每条遵循「操作 → 断言」闭环：
   - **操作优先用元素目标**：从最近一次 `get_app_state` 的 `state_id` + 元素 index 发
     `left_click` / `type` / `set_value` / `perform_action`——元素级操作后台安全、不抢焦点。
   - **坐标点击只在截图可定位时用**：坐标必须取自最近一次截图的光栅像素，不得凭空估算。
   - **文本输入的平台差异**：Windows/Linux 上无元素目标的键盘输入要求应用在前台，
     优先选可编辑元素目标（textfield）用 `type`；确需快捷键（如 Ctrl+Shift+P）先 `key` 前确认窗口已聚焦。
   - **断言以重新 `get_app_state` 的树为准**（元素文本、可见性、计数、菜单项），不要凭 URL/日志想当然。
   - 关键路径（提交、切换面板、弹窗）操作后必须重新观察确认结果。
4. **失败排查**：失败时 `screenshot` 留证，并区分「测试操作方式不对」还是「被测功能确实有 bug」：
   前者换一种可访问的操作方式重试；后者记录为失败项。截图不可见时仍以无障碍树为最终依据。
5. **清理**：关闭**自己启动的**测试实例（`terminate` / taskkill 对应 pid），
   用户已有实例与数据一律不动；恢复启动前状态。

## 规则

- **不修改被测源码**；确需修改时先向用户说明并获得同意。
- 优先语义化定位（按钮文本、label、菜单名），不依赖像素坐标。
- 每个用例独立可复现：操作前恢复已知状态（重开面板 / 重启应用）。
- 被测应用有持久化（配置、localStorage、DB）时注意用例间状态污染，必要时用独立 user-data-dir。
- 需要登录 / 网络的服务不可达时，明确标注「跳过（环境限制）」。
- 测试用临时进程用 `run_command` 清理，不留残留。

## 完成判定

- 验收清单每条给出 通过 / 失败 / 跳过(原因)。
- 失败项附截图（或无障碍树片段）与根因分析（测试操作问题 or 被测 bug）。
- 输出汇总：通过 X / 共 Y，以及遗留失败项清单。

## OurCode IDE 自测场景清单（常用验收项）

- **启动与主界面**：窗口出现、无错误弹窗；侧栏面板齐全（一人公司 / 浏览器 / MCP 服务器 / 技能 / 使用统计 / 任务面板 / 代码管理 / 文件变更历史）；菜单栏齐全（文件 / 编辑 / 选择 / 查看 / 转到 / 运行 / 智能体 / 终端 / 扩展 / 帮助）。
- **聊天**：输入框可聚焦输入，Enter 发送；模型切换（按钮+下拉）、思考档位、图片/文件添加按钮可用。
- **MCP 面板**：服务列表出现、连接状态文本正确。
- **设置**：API 配置、偏好设置入口可打开、字段可编辑。
- **窗口控制**：最小化 / 还原 / 关闭按钮可用（关闭测试用「关闭」按钮而非直接杀进程）。
